# 0.3.2 基础控制恢复

本版恢复已核对物模型的日常控制，基础功能默认启用，工程参数仍不展示。0.3.1 新增设备可见性和只读状态；本版继续补齐控制能力，替代其“新增冰箱、洗衣机均只读”的限制。

| 设备 | 默认显示的基础控制 | 说明 |
| --- | --- | --- |
| 空调 | 开关、工作模式、目标温度、风速、上下/左右扫风、节能、睡眠 | 原有型号保留，并补充本次国内列表中的 7 种型号；根据型号显示档位或风速百分比 |
| 冰箱 | 冷藏/冷冻/变温室设定温度、速冷、速冻、童锁 | 按各型号范围和步长校验；实际温度和门状态仍为传感器 |
| 洗衣机 | 电源、洗涤程序、启动洗涤、暂停洗涤、洗涤温度、脱水转速、漂洗次数、童锁 | 启动/暂停为独立按钮；待机、完成只作状态，禁止当作控制值发送 |
| 集成洗衣机 | 上述洗涤控制，以及烘干程序、启动烘干、暂停烘干、烘干程度 | 仅显示型号实际提供的功能 |
| 门锁 | 电子反锁、门锁语音音量、门铃音量、逗留提醒、提醒时间档位 | 同时保留门状态、电量；电子反锁开关不等于远程开门 |

## 查看和操作

刷新浏览器，进入 **设置 → 设备与服务 → TCL Smart Home → 对应账号 → 设备**。日常操作在设备页“控制”区域；状态读数位于“传感器”，云端在线位于“诊断”。无需删除集成或重新扫码。

洗衣机选择程序及温度、转速后，点击“启动洗涤”；需要暂停时点击“暂停洗涤”。集成洗衣机的烘干操作有独立按钮。具体程序间的兼容性、童锁、关门和远程控制条件由设备及云端决定；有控制入口不代表设备一定接受所有组合。插件没有绕过设备侧条件，也没有模拟成功状态。

## 门锁远程开门的接口限制

当前物模型中 `openDoor` 是独立服务，带 `requestId` 和 `userId` 参数，并明确标注为服务端高级指令、APP 不能直接发送。现有 CLI 和本集成的接口仅提供属性控制，没有该服务的授权、请求标识获取和结果确认协议。

因此本版恢复的是已明确可写的日常设置，**没有远程开门/主锁舌开闭按钮**。`mainLockStatus`、`reverseLockStatus` 不能仅因标记为 rw 就用来代替开锁。接入远程开门仍需要厂商开放接口文档，明确认证、请求标识流程、有效期和结果回执。应用密钥、安全传输、服务权限和输入校验要求继续保留。

## 升级行为

- 旧的温度设定值、程序只读实体替换为对应 number/select 控制；旧实体记录和历史保留并停用，避免重复显示。如有自动化引用旧传感器，请改用新实体。
- 先前由集成停用、现已适配的基础实体会恢复；用户手动停用的实体保持原选择。
- 云端没有上报状态时仍显示“未知”，不会虚构默认温度、程序或运行状态。默认每 30 秒同步。
- 以精确的产品与属性结构限定控制范围；未知属性、工程参数、密钥管理和未经接入的远程开门服务继续不开放。

## 验证范围

114 项测试通过；在 HA 2026.9.4 的独立运行环境中验证了模拟温度写入、洗涤启动暂停、电子反锁设置、无效状态拒绝、权限与实体迁移。真实环境只检查安装、设备发现和控制页面，不向真实设备发送控制指令。全部型号的实机操作及不同程序的组合仍需后续联调。

## 安装

0.3.0/0.3.1 用户保留现有账号和本地应用密钥，覆盖组件目录并重启 HA。新安装者按 README 配置自己的应用密钥。不要使用含旧嵌入密钥的 0.2.x 安装包。安装包不含本机令牌、账号配置或 secrets.yaml。
