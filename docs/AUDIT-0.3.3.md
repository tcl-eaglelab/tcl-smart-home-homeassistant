# 0.3.3 代码精简与安全审查

审查日期：2026-11-03。范围：当前自定义集成源码、凭据迁移工具、发布材料，以及本机 HA 2026.9.4 中选定的 12 个 Python 包。结论：代码可整理为供受控测试的安装包，但 **不能认定已经完成公开发布的安全合规审查**。

## 代码精简

- 删除 `lock.py`：该平台始终返回空实体。门锁电子反锁、音量、逗留提醒通过 switch/select 提供，不受影响；没有远程开门接口。
- 删除 `text.py`：能力策略不生成 text 实体且后端拒绝文本写入，是不可达平台。
- 从平台加载列表移除 lock/text；删除 7 个已无运行时引用的旧辅助函数：旧空调/门锁识别、只读/数值/文本/布尔类型判断和旧控制值转换。布尔编码等实际控制校验仍由统一能力策略执行。
- 删除 2 项仅覆盖旧函数的测试，保留并更新“报警设置不能生成开锁控制”回归，112 项现行测试通过。
- 保留所有已审核产品规则、基础控制、诊断、语言资源、二维码界面和品牌图片。英文翻译与 strings.json 的一致内容是 HA 资源结构需要，非误复制。
- 旧版本能力与安全说明标为历史记录，首页以本审查和 0.3.2 基础控制说明为准。修正 changelog 顺序和安装说明中的 HACS 已上架暗示。
- 新增可复用打包工具；排除缓存、HA 配置、令牌、备份、工作脚本及日志。新增 CI Ruff 检查和 Python 依赖更新提醒。

## 已核查的安全措施

| 范围 | 实现与验证 | 边界 |
| --- | --- | --- |
| 凭据 | 发布代码无默认应用密钥；使用本地 YAML/!secret；诊断仅输出计数与布尔状态 | !secret 与 HA config-entry 文件不是加密存储；须保护主机和备份 |
| 网络 | HTTPS、证书校验、固定域名/端口允许列表；拒绝 HTTP 重定向 | 依赖宿主 HA 的 TLS/HTTP 库；不是独立沙箱 |
| 写入 | 产品与 schema 匹配、布尔/枚举/数值范围/步长/有限值校验；不接受任意文本或结构写入 | 型号协议和设备联锁仍由厂商负责；未做全部实机程序组合测试 |
| 洗涤动作 | 只把运行值 2、暂停值 1 做成按钮；待机/完成不能当命令发送 | 无真实设备启动/暂停试验；模拟传输验证通过 |
| 权限 | 原始属性服务仅管理员且要求用户上下文；实体动作使用 HA 标准权限 | 有 HA 实体控制权限的用户/自动化可操作已开放功能，电子反锁没有额外管理员限制或二次确认 |
| 门锁 | 仅开放明确的设置；不将锁舌状态映射为开锁，不开放密钥管理和 openDoor 服务 | 远程开门需要厂商独立授权协议，当前不支持 |
| 日志 | 自有 HTTP/业务错误不回显正文、令牌、URL；诊断不导出完整设备对象 | 代理、HA 调试、主机或服务端日志不受插件全面控制 |
| 二维码 | 同源 HTTPS 地址检查、图片 no-referrer；按钮交给 HA 原生配置流程 | 浏览器直接访问厂商图片；上游重定向和图片请求数据由厂商处理 |
| 请求 | 有界并发、超时、429 和 5xx/连接失败退避 | 74 台设备按 30 秒刷新可产生约 150 次状态请求/分钟，另有列表/模型请求；需确认厂商配额，必要时调大间隔 |
| 前端 | 只提供静态展示脚本，不自建匿名控制接口，不覆盖全局 HA 原型 | 使用 HA 私有对话框 DOM，需持续兼容验证；不等于符合 HA Core 收录要求 |

## 本次发现：宿主依赖存在已知漏洞公告

使用 pip-audit 查询本机实际安装版本，检查 12 个选定包，结果没有跳过包；3 个包共命中 **12 条去重公告**。这是版本匹配结果，不代表 12 条均能在本插件路径中被利用。

| 包 | 当前版本 | 公告匹配 | 建议 |
| --- | --- | --- | --- |
| aiohttp | 3.14.3 | 8 条：连接/资源耗尽、cookie、Python 解析器请求走私等 | 数据库给出的修复版本为 3.14.4；采用包含该修复或更高兼容版本的 HA 镜像 |
| certifi | 2026.7.22 | 1 条：证书信任库包含受影响根证书链 | 公告初修版本 2026.10.18，正文建议 2026.10.19 或以后；需确认 HA 实际证书路径与镜像 CA 更新 |
| cryptography | 48.0.1 | 3 条：证书验证/密码学特定 API 问题 | 分别在 49.0.0、50.0.0 修复；选择覆盖所有公告且与 HA 兼容的镜像 |

公告示例：[aiohttp 资源耗尽](https://github.com/advisories/GHSA-2g87-pp6c-29x5)、[certifi 信任库](https://github.com/advisories/GHSA-6q48-6c7w-9gw2)、[cryptography 证书约束](https://github.com/advisories/GHSA-m2h6-j472-rp4c)。完整版本与公告编号见同包 `AUDIT-0.3.3-evidence.json`。

插件 manifest 没有自装第三方运行依赖，复用 HA 提供的库。**不要在运行容器里直接强行 pip 升级来覆盖 HA 的依赖约束。** 应备份 HA，选定包含修复的官方镜像，在隔离环境验证扫码、同步、控制和旧配置迁移，再升级并重新扫描。当前镜像未在本次任务中更换；这一风险仍未解决。本次没有扫描全部 HA 可选集成、操作系统镜像或所有依赖树。

## 静态审查与验证结果

- Bandit 扫描组件与工具：9 条 LOW/B105；逐项核对为 access_token/refresh_token/token_expires 等配置键、密钥引用名及“指纹密码”等界面文案，不是凭据值。没有中/高等级命中，未屏蔽规则；原始结果保留供复核。
- pytest：112 项通过。Ruff、Black 和 JSON 检查通过。
- HA 2026.9.4 隔离运行测试：管理员/非管理员/无身份原始服务、值校验、按钮写入和注册表迁移通过，云端被模拟。
- 二维码桌面/手机合成浏览器测试：居中、刷新、未扫码提示状态、无箭头、其他集成不受影响通过；非真实扫码测试。
- 发布前扫描已知历史密钥、本机当前令牌/应用密钥及明显私钥/JWT模式；包内不含 HA 私有配置。扫描有范围限制，不是完整秘密识别保证。
- 本次没有执行真实设备控制、完整渗透测试、HA 官方审核，也没有重启或替换当前运行中的 0.3.2；0.3.3 是本次整理后的安装/源码包。

## 公开发布前仍需完成

1. **宿主漏洞修复**：先验证并升级包含依赖补丁的 HA 镜像，重新扫描。
2. **厂商授权与凭据**：确认 API 调用、开放源码、应用 ID/密钥使用与分发权限；旧包曾含密钥，按厂商流程评估撤销/轮换并清理已公开历史。迁移到 !secret 不会使旧密钥自动失效。
3. **刷新协议整改**：国内/海外刷新接口仍按现有协议将 appSecret/clientSecret 放在 HTTPS URL 参数，可能进入服务端或代理日志。需厂商支持请求体/头部或正式公共客户端授权流程；插件不能单方面改协议后宣称修复。
4. **许可与商标**：核实原 CLI、国家表、物模型数据、TCL logo 的来源许可与必要署名。仓库的 MIT 声明不代表所有第三方材料已获得再许可权。
5. **隐私与撤销**：准备数据类别、区域路由、目的、保留和退出说明；验证云端授权撤销。删除 HA 集成不代表令牌在云端作废。国内个人信息保护、海外 GDPR 等适用性需由负责主体结合实际发布方式核实。
6. **渠道与官方要求**：启用私密漏洞报告渠道；核实仓库 URL/维护人；在真实仓库运行 HACS/hassfest CI。当前是自定义集成，未获 HA 官方 Core 收录；私有 DOM、认证协议、文档和测试仍需按官方要求处理。

因此适合表述为“已完成本次源码安全检查并列明风险的测试包”，不应宣传为“已认证”“完全安全”或“全部合规”。
